# 04 · 실전 작업 영수증·회고 아카이브

<aside>
🔒

이 아카이브는 **실전 작업의 사실·사용자 피드백·해석 변화·수정 결과를 보존하는 관찰층**입니다. 공용 실행 카드, 작품별 활성 규칙, 초고 생성 공식으로 자동 사용하지 않습니다.

</aside>

## 역할 분리

1. **원본 작업 영수증 인덱스**는 각 작품에 흩어진 불변 영수증을 링크하고 당시 상태를 보존합니다.
2. **실전 작업 회고 사례**는 작업 순서, 실패한 시도, 사용자 피드백 원문, 초기 해석과 수정된 해석, 효과 귀속과 미확정점을 다시 정리합니다.
3. **실전 가설 후보**는 여러 사례에서 재검증할 질문만 보존합니다. 공용 실행 카드로 자동 승격하지 않습니다.

## 핵심 경계

- 사용자 피드백 원문과 당시 해석, 후속 해석을 분리합니다.
- 성공 사례뿐 아니라 폐기된 수정, 무효한 카드 적용, 기계화·표면 모방·효과 불명 사례를 함께 저장합니다.
- 한 작품의 사례를 다른 작품에 바로 적용하지 않습니다.
- 대사·캐릭터 사례는 수정 대사 예문, 말투표, 반응 순서, 필수 침묵·반문을 저장하지 않습니다.
- 공용 가설 후보는 복수 작품·반례 검증 전까지 `진단 질문`일 뿐 실행 지시가 아닙니다.

## 회고 생성 조건

- 사용자 피드백으로 최초 진단이 바뀐 경우
- 적용 기법이 실패·과잉·기계화·표면 모방을 만든 경우
- 카드 효과와 작품 맥락의 효과를 구분하기 어려운 경우
- 같은 문제가 여러 회차에서 반복된 경우
- 10화·50화 감사에서 장기 결과를 다시 판정한 경우

단순 NO_OP, 이름·호칭 교정, 성공 여부가 명확한 기계 검사만으로는 회고를 만들지 않습니다.

## 회고 본문 필수 순서

`원본 사실 → 작업 순서 → 사용자 피드백 원문 → 당시 해석 → 후속 해석 → 유지·폐기된 시도 → 효과 귀속 → 작품 전용 교훈 → 재검증 질문 → 불확실성 → 승격 경계`

## 공용 승격 금지

> 회고가 풍부하다는 이유만으로 실행 카드를 만들지 않습니다. 복수 작품에서 독립적으로 재현되고 반례가 확보된 뒤에도, 먼저 생성 규칙이 아니라 퇴행·결함을 찾는 진단 원칙 후보로 검토합니다.
