# 웹소설 참고작 정본 연구 저장소

참고작 원문을 직접 재검증하며 CHARACTER·RELATIONSHIP·EVENT·STORY·PROSE·TECHNIQUE 여섯 트랙과 원천 장면·PSE·PVAR·Macro·Micro·TH를 누적하는 비공개 연구 저장소입니다.

## 연구 시작점

1. 최신 `REFERENCE_RESEARCH_ANALYSIS_SOP`
2. `REFERENCE_RESEARCH_REPOSITORY_CONTRACT`
3. `REFERENCE_WORK_MODEL_SCHEMA`
4. `REFERENCE_RESEARCH_ANONYMITY_CONTRACT`
5. `REPOSITORY_MANIFEST.yaml`이 가리키는 현행 검색 계약과 대상 `REF`의 작품 모델·원천 장면·PSE/PVAR·TH·최근 연구 영수증

작품의 첫 진입, 신규 인물·관계·조직·공간·직업·능력·규칙의 첫 제시 또는 재온보딩을 연구할 때는 `indexes/initial_onboarding_research.md`를 사용합니다. 이 인덱스는 `좋은 1화`의 공통 문형이나 사건 템플릿을 만드는 문서가 아니라, 각 작품에서 독자가 무엇을 먼저 학습해야 했는지와 그 문제를 여섯 트랙이 어떻게 해결했는지를 기존 작품 모델에 독립적으로 저장하도록 라우팅하는 계약입니다. 작품별 근거가 성립하기 전에는 다른 REF의 성공 방식을 현재 작품의 정답으로 가져오지 않습니다.

집필 검색에서 Source Scene을 사용할 때는 `indexes/scene_retrieval_contract.md`를 먼저 읽습니다. Source Scene의 실제 결합 사슬은 연구를 위한 `observed_chain`이며 집필용 `recommended_chain`이 아닙니다. 장면 전체 일치나 성공 장면의 beat 순서를 요구하지 않고, 현재 문제와 맞는 부분만 찾은 뒤 불일치 경계와 가져오지 말아야 할 요소를 함께 기록합니다.

## 공통 배치 운영

10화 고정 배치를 전역 기본값으로 사용하지 않습니다. 모든 참고작은 **적응형 대구간 순회 + 변화 밀집 구간 정밀 재독 + 완독 후 작품 전체 왕복 채굴**을 기본 운영으로 합니다.

- 기본 원문 순회 단위는 `40~80화`입니다.
- 대구간에 포함된 원문은 전부 직접 읽습니다. 속도 향상은 원문을 건너뛰는 방식이 아니라 반복되는 저변화 장면의 기록 밀도를 낮추는 방식으로 얻습니다.
- 캐릭터 판단 기준의 변경·오판·복귀, 관계 권리 이동, 사건 인과 전환, 기존 TH의 변형·실패·비용·반례, 장기 Payoff, POV·정보 접근권·대사·지문·문장·문단 변주가 발생한 구간만 더 좁게 확대 재독합니다.
- 같은 메커니즘의 반복은 기존 작품 모델·TH에 좌표와 변형을 보강하고, 회차 수에 비례해 신규 Source Scene·PSE·PVAR·Macro·Micro·TH를 만들지 않습니다.
- PSE는 기존 PROSE 요약이나 Macro/Micro에서 실제 문법·문장·문단 선택이 손실될 때만 만들고, PVAR는 같은/가까운 기능의 서로 다른 PSE를 비교할 가치가 있을 때만 만듭니다.
- Macro는 독립 재독 가치가 있을 때만, Micro는 Macro로 사라지는 결정적 표현이 있을 때만 만듭니다.
- 유사 사례만 반복되면 신규 등록보다 포화·반례 탐색을 우선합니다.
- 1차 완독 뒤에는 다시 10화 단위로 재주행하지 않고 미확인 질문과 활성 TH를 들고 초반·중반·후반을 왕복합니다.

배치 크기는 운영 단위이며 SOP의 공식 연구 모드를 대체하지 않습니다. 작품별 인덱스가 더 구체적인 배치 범위를 지정하면 해당 인덱스를 따릅니다.

## PROSE 저수준 증거층

`REFERENCE_WORK_MODEL_SCHEMA_v2`부터 PROSE에는 두 하위층을 둡니다.

- `PSE`: 짧은 연속 구간에서 의미 단위가 절·문장·지문·문단으로 실제 실현된 방식을 보존합니다.
- `PVAR`: 같은 작품 안에서 동일하거나 가까운 기능을 서로 다른 표면으로 푼 PSE들을 비교합니다.

이 층의 목적은 좋은 어미나 문형을 모으는 것이 아닙니다. 같은 기능을 작가가 왜 서로 다른 시제·조사·부사·연결·종결·문장 경계·문단 경계로 풀었는지 다시 원문에서 검증할 수 있게 만드는 것입니다. `사고 단위 ≠ 문장 단위 ≠ 모바일 화면 문단`을 구분하고, 모바일 가독성을 고정 글자 수나 토막문장 규칙으로 환원하지 않습니다.

## 집필 직전 표현 검색

참고작을 실제 집필에 사용할 때는 먼저 **대상 작품의 승인 문체·시점 계약과 최근 확정 원고**를 native anchor로 읽습니다. 그 다음 사건·스토리 문제, 장면 결합 문제, 장면 표현 문제, 필요 시 산문 실현 문제를 분리합니다.

- 사건·스토리 문제: EVENT·STORY·RELATIONSHIP·CHARACTER·TH에서 조회
- Source Scene 결합 문제: `indexes/scene_retrieval_contract.md`에 따라 전체 일치 대신 부분 문제로 검색하고 `matched_problem / mismatch_boundary / usable_judgment / do_not_import`를 기록
- 장면 전체 표현 문제: `indexes/expression_retrieval.md`에 따라 POV·정보권·서술 거리 호환성을 먼저 검사한 뒤 PROSE·Macro·Micro·표현 장면을 조회
- 문장·지문·문단 실현 문제: `indexes/prose_realization_retrieval.md`에 따라 PVAR → 서로 다른 PSE → source scene 순으로 **원문 재진입 좌표를 찾음**
- 구조 참고 REF와 표현 참고 REF는 자동으로 같다고 보지 않음
- 한 REF의 한 회차만으로 작품의 기본 표현법이나 현재 장면의 정답 표면을 확정하지 않음
- 현재 문제와 가까운 복수 회차에서 변형·예외·복귀를 확인하고, 복수 REF를 쓸 때는 각 작품을 먼저 독립적으로 원문 재독한 뒤 비교함
- 복수 REF·복수 회차는 고정 할당량이 아니며 같은 표면만 반복되면 반례·다른 실현·조건 차이를 우선함
- 실제 표현 판단에 사용할 후보는 해당 회차 전체를 처음부터 끝까지 직접 읽고, 필요한 경우 인접 회차까지 확장함
- 회차 전체에서 대사·지문·내면·설명·행동·효과음·UI·문단·문장이 어떻게 교대하는지와 각 구간의 어휘·문법·생략·절 결합·문장 경계를 함께 봄
- 외부 참고작은 대상 작품의 기본 목소리를 대신하지 않음
- 임시 표현 패킷은 원문 좌표·호환성·불일치 경계·주의사항을 좁히는 검색 메모일 뿐, 그 추상 결론에서 문장을 복원하는 실행 컴파일본이 아님
- PVAR의 표면 차이를 `-지만 → -니까 → 현재형` 같은 순환표로 컴파일하지 않음
- **파생 연구층만 읽고 곧바로 산문을 생성하지 않음.** 실제 초고 판단에서는 이번 실행에서 직접 재독한 참고작 원문 회차와 대상 작품 native anchor를 함께 참조함
- 참고작의 고유 문장·말버릇·사건 배열은 복제하지 않고, 원문 재독으로 확보한 선택 폭을 대상 작품의 인물·세계·관계·직업 감각 안에서 새 표현으로 만듦
- 초고 후 `결합 강제 감사`와 POV 계약 위반·외부 문체 혼입·의미 선점·중복 해설·주제 설명 대사·설명성 화말·기계적 시제/어미 다양화·이유 없는 연속 단문화를 감사

표현 facet은 새 기법 ID가 아니라 검색 질문을 만드는 좌표입니다. PSE/PVAR는 반복된 실제 저수준 손실을 해결하기 위해 승인된 PROSE 하위층이며, 이후 추가 표현 스키마는 다시 구조적 검색 실패가 확인되기 전에는 만들지 않습니다.

## 작품 익명성

신규 일반 연구 파일·인덱스·영수증·커밋에는 실제 작품명·저자명·인물명·조직명·기술명을 쓰지 않습니다. 작품은 `REF`, 원천은 `SRC` 코드로 식별합니다. 실제 작품명과 원천 파일명은 비공개 봉인 신원 맵에만 두고, 일반 연구층은 원천 행 범위와 SHA-256으로 다시 원문에 진입합니다.

## 현재 연구 진행

작품별 현재 범위와 미확인 질문은 각 `works/REF-XX/indexes/research.md`, 완료된 작품은 `works/REF-XX/COMPLETION.md`, 그리고 최근 연구 영수증을 정본으로 사용합니다. 루트 README나 레거시 색인의 예시 범위를 현재 진행 상태로 간주하지 않습니다.

## 레거시 경계

- `history/`는 Notion 내보내기 원형과 입력 자료를 보존합니다.
- `catalog/`는 과거 이관 색인이며 일부 실제 식별자가 남아 있는 **익명화 미완료 레거시층**입니다. 신규 연구나 집필 검색의 시작점·실행 권위로 사용하지 않습니다.
- `catalog/tables/execution-cards.csv`의 `execution_structure`, `completion_conditions`, `recommended_combinations` 등은 과거 실행층의 기록이며, 현행 계약과 원문 재검증 없이 집필 명령·자동 발동 규칙·권장 장면 뼈대로 사용하지 않습니다.
- 루트에 남아 있는 과거 `REFERENCE_RESEARCH_REPOSITORY_CONTRACT_v1.1_*`, `v1.2_*` 부속서는 역사적 호환 기록입니다. 현행 적용 부속서는 `REPOSITORY_MANIFEST.yaml`이 가리키는 버전 하나뿐입니다.
- 신규 연구와 종료 보고는 `works/`의 익명 연구 파일과 연구 영수증을 기준으로 판정합니다.
- 레거시층의 작품명·고유명은 신규 연구 파일이나 커밋 메시지로 복사하지 않습니다.

참고작의 문장·고유명·사건 배열을 결과물에 그대로 복제하지 않습니다.
