# 산문 실현 검색 인덱스

> 목적: 장면의 사건·관계·POV 문제는 이미 정해졌는데도 실제 문장·지문·문단이 자동 행동문, 자동 판단문, 토막문장, 과밀 블록, 기계적 시제·어미 다양화로 회귀할 때, 같은 작품의 PVAR·PSE·원문으로 재진입해 **표면 공식이 아니라 선택 공간**을 복원한다.

## 1. 적용 범위

이 인덱스는 다음 문제가 핵심일 때 사용한다.

- 같은 의미를 여러 독립 완결문으로 잘라 사고가 끊김
- 문장을 결속했지만 모바일 화면 문단이 과밀해짐
- `~다` 반복을 피하려고 현재형·이유형 종결·접속 표현을 기계적으로 섞음
- 같은 기능이 `A가 아니라 B였다`, `-지만`, `-니까` 같은 새 자동 문형으로 굳음
- 문단 길이만 맞추고 의미 단위·절 결합·앞뒤 블록 리듬을 잃음

장면 전체의 POV·대사·정보 공개·상태 변화 문제가 먼저라면 `indexes/expression_retrieval.md`를 우선한다.

## 2. 기본 원칙

- `PSE`는 원문 실현 증거다.
- `PVAR`는 같은/가까운 기능의 서로 다른 PSE를 비교하는 변형군이다.
- PSE/PVAR는 좋은 문장·어미·문단 패턴 사전이 아니다.
- 정확한 표면은 source scene과 원문 좌표에서 다시 읽는다.
- **PSE·Source Scene의 저장 범위는 추출 단위이지 기본 독해 단위가 아니다.** 문장·지문·문단 선택을 판단할 때는 먼저 그 사례가 속한 회차 전체를 읽고, 필요하면 인접 회차까지 확장한다.
- **읽기는 크게, 추출은 작게 한다.** 회차 맥락은 임시 선택 조건으로 사용하고, 그 자체를 새 영구 연구층이나 회차 요약 DB로 만들지 않는다.
- 외부 참고보다 대상 작품의 native anchor가 우선한다.

## 3. 검색 질문을 기능으로 쓴다

표면 형태를 먼저 검색하지 않는다.

나쁜 질문:
- `-지만 뒤에 -니까를 쓰는 사례`
- `현재형을 섞은 문단`
- `100자 이하 문단`

좋은 질문:
- `증거처럼 보이는 정보를 확인한 뒤 판단을 유보하고 이유를 붙이는 구간`
- `같은 사고를 유지하면서 화면 블록만 둘로 푸는 구간`
- `직전 판단의 이유를 뒤늦게 보충하는 구간`
- `초점 인물의 판단 거리가 가까워질 때 시제가 실제로 달라지는 구간`

## 4. 검색 순서

1. 대상 작품 native anchor에서 기본 시제·서술 거리·문단 호흡을 다시 읽는다.
2. 현재 장면의 **의미 기능**을 한 문장으로 쓴다.
3. 같은 REF의 PROSE 모델에서 관련 PVAR를 찾는다.
4. PVAR가 있으면 서로 다른 실현을 가진 PSE를 기본 1~3건 고른다.
5. PVAR가 없으면 관련 PSE를 찾고, 비교 가능한 다른 PSE가 있는지 확인한다.
6. 선택한 PSE의 source scene·원문 좌표를 확인한다.
7. **해당 사례가 속한 회차 전체를 처음부터 끝까지 읽는다.** 사례가 회차 경계의 선행 제시·후속 회수·화말과 직접 결합하면 필요한 인접 회차까지 확장한다.
8. 회차 전체에서 `회차 기능 / 장면 배열 / 후보 블록의 위치 / 이미 제시된 정보 / 압축↔확대 파형 / 대사↔지문 밀도 변화 / 다음 전환·화말 압력`을 임시 `episode_context_envelope`로 기록한다.
9. 그 뒤 source scene과 관련 장면 블록으로 내려가고, 필요하면 앞뒤 2~3개 문단까지 다시 정밀 재독한다.
10. 아래 비교축을 기록한다.
11. 설명되지 않는 차이는 `선택 조건 미확인`으로 남긴다.
12. 참고작을 닫고 대상 작품 native anchor에서 새 문장을 쓴다.
13. 초고 후 기계 변주·과현장화 감사를 수행한다.

## 5. 비교축

### 5.0 회차 맥락과 산문 파형

- 이 블록은 회차의 도입·확대·전환·회수·보상·화말 중 어디에 놓이는가.
- 현재 정보가 이 자리에서 처음 제시되는가, 앞 장면에서 이미 충분히 경험시킨 정보를 짧게 회수하는가.
- 같은 회차에서 장면별로 서술 밀도·대사 밀도·내면 접근·환경 묘사가 어떻게 달라지는가.
- 왜 이 블록은 확대되고 다른 블록은 압축되는가. 그 차이를 선행 제시량·새 판단 비용·다음 전환 압력으로 설명할 수 있는가.
- 짧은 문장·긴 문장·짧은 지문·긴 지문이 국소 취향이 아니라 회차 내 역할 변화와 연결되는가.
- 후보 범위만 읽었을 때의 해석과 회차 전체를 읽은 뒤의 해석이 달라졌는가.

### 5.1 의미 단위와 절 결합

- 관찰·감각·기억·비교·판단·유보·행동·내면 중 무엇이 있는가.
- 몇 개 의미가 한 절·한 문장에 결합되는가.
- 역접·인과·조건·양보·병렬·부연을 접속사, 연결 어미, 문맥 중 무엇으로 처리하는가.

### 5.2 조사·부사·초점

- `은/는`, `이/가`, `도`, `만` 등이 무엇을 대비·한정·재초점화하는가.
- `이미`, `아직`, `정작`, `오히려`, `애초에`, `굳이` 등이 시간축·판단 강도·대비를 실제로 바꾸는가.

### 5.3 시제·상·양태·종결

- 장면 기본 시제는 무엇인가.
- 시제가 바뀌었다면 현재 판정·직접 사고·회상·일반화 등 실제 이유가 있는가.
- 단정·추측·유보·가능성은 어디에 표시되는가.
- 완결형·이유형·파편형·의문형·명사형이 앞뒤 문장과 어떤 관계를 만드는가.

### 5.4 문장 경계

- 왜 여기서 마침표를 찍었는가.
- 같은 사고를 문장 안에서 더 이어도 되었는데 끊은 이유가 있는가.
- 반대로 여러 정보를 한 문장에 넣은 이유가 있는가.

### 5.5 문단·모바일 화면 블록

- 사고 단위와 문장 단위와 화면 문단이 일치하는가.
- 하나의 사고를 두 화면 문단으로 풀었는가.
- 짧은 블록 뒤 중간·긴 블록, 큰 블록 뒤 대사·단문이 어떻게 배치되는가.
- 모바일 가독성이라는 작가 의도는 원문만으로 확정하지 않고 결과와 상대적 블록 대비를 관찰한다.

## 6. PVAR 사용법

PVAR에서 가져오는 것은 `정답 문형`이 아니라 다음이다.

- 같은 기능이 어떤 서로 다른 표면으로 실현되었는가.
- 공통 조건과 달라진 조건은 무엇인가.
- **각 PSE가 속한 회차에서 선행 제시량·장면 역할·압축/확대 위치가 어떻게 달랐는가.**
- 어떤 차이는 설명 가능하고 어떤 차이는 아직 미확인인가.
- 반복되던 표면을 작가가 언제 깨는가.
- 한 문형으로 압축하면 어떤 선택 폭이 사라지는가.

PVAR에 사례가 많아도 실제 선택 조건이 설명되지 않으면 랜덤 순환표로 사용하지 않는다. 국소 문장 차이만으로 선택 조건을 확정하지 않고, 회차 전체를 읽어도 설명되지 않는 차이는 `선택 조건 미확인`으로 유지한다.

## 7. 집필 직전 임시 패킷

현재 장면에는 다음만 남긴다.

- native anchor 1~2개
- 현재 의미 기능 1문장
- PVAR 0~1개
- 서로 다른 PSE 1~3개와 source 좌표
- 각 사례의 `episode_context_envelope` 핵심: 회차 역할, 후보 위치, 선행 제시량, 압축/확대 상태, 다음 전환 압력
- 각 사례에서 확인한 선택 이유
- 아직 미확인인 차이
- 현재 장면에서 지켜야 할 시간축·서술 거리·관계 조건
- 금지할 자동 문형 또는 과교정

어미·접속 표현 목록이나 회차 요약 전문을 패킷에 넣지 않는다.

## 8. 초고 후 감사

다음이 보이면 참고작 표면을 다시 늘리는 대신 현재 문장을 재검토한다.

- 과거형이 자연스러운 장면에서 `~다` 반복을 피하려고 현재형을 섞음
- `-지만 → -니까 → -는데`가 의미와 무관하게 순환함
- 모든 판단이 짧은 독립 판정문으로 끝남
- 과분절을 고친다고 토막 완결문을 한 긴 문단에 모음
- 문장 결속을 살린다고 큰 서술 블록이 연속됨
- 모바일 가독성을 이유로 관찰·판단·이유를 각각 독립 문단으로 쪼갬
- PVAR의 한 사례를 다음 회차의 고정 뼈대로 반복함
- PSE의 국소 문장이 짧다는 이유만으로 대상 장면도 단문화함
- `디테일 개선`을 이유로 모든 반응·전환·신체 이상을 새 사건처럼 확대하거나 행동 비트로 현장화함
- 참고 사례가 앞 장면에서 이미 충분히 제시된 정보를 압축 회수한 것인지 확인하지 않고 그 압축 표면만 모방함
- 반대로 참고 사례가 처음 제시한 중요한 경험을 확대했다는 이유만으로 대상 작품의 반복 정보까지 다시 확대함

## 9. 연구층 생성 조건

PSE/PVAR는 필요한 만큼만 만든다.

- 기존 PROSE·Macro·Micro에서 실제 저수준 선택이 손실되는가.
- 원문 좌표가 정확한가.
- PSE는 다시 비교할 문법·문장·문단 선택이 있는가.
- PVAR는 최소 두 PSE가 같은/가까운 기능을 서로 다르게 풀고 있는가.
- 파일 수 증가가 아니라 원문 재독과 집필 판단이 좋아지는가.

`episode_context_envelope`는 집필·비교 직전의 임시 독해 메모이며 새 ID·새 파일 유형·새 회차 데이터베이스가 아니다. 조건을 만족하지 않으면 새 PSE/PVAR를 만들지 않고 기존 PROSE와 source scene을 사용한다.

## 10. 완료 판정

검색을 끝낼 때 다음을 말할 수 있어야 한다.

- 현재 장면의 기본 시간축·서술 거리는 무엇인가.
- 비교한 PSE들이 같은 기능을 어떻게 다르게 실현했는가.
- **각 사례가 속한 회차 전체에서 왜 그 위치에 그 정도로 압축·확대되었는가.**
- 그 차이 중 어떤 것은 선행 제시량·장면 역할·다음 전환 압력으로 설명되고 어떤 것은 미확인인가.
- 사고 단위·문장 단위·화면 문단이 각 사례에서 어떻게 달랐는가.
- 참고작 표면을 복사하지 않고 현재 작품에서 새로 선택해야 할 것은 무엇인가.

## 11. SOP v7.1 문장 경계·독자 선행 지식 보정

이 절은 §4~§8의 산문 검색과 감사를 보강한다. 목표는 단문 수를 줄이거나 복문을 늘리는 것이 아니라 **현재 의미·운동 사슬과 독자 학습 상태에 맞는 경계 선택을 복원하는 것**이다.

### 11.1 회차 맥락 envelope 보강

임시 `episode_context_envelope`는 다음을 명시적으로 포함한다.

- `serial_position`: 작품 내 위치. 단독 우선순위가 아닌 보조 좌표
- `episode_role`: 도입 / 초기 온보딩 / 정착 운용 / 재온보딩 / 전환 / 회수 / 보상 / 화말 등
- `reader_prior_knowledge`: 후보 직전까지 독자가 이미 학습한 정보
- `onboarding_load`: 현재 블록에서 새로 학습·분류해야 하는 정보와 판단 비용
- `first_introduction_or_callback`: 첫 제시·재소개인지, 이미 학습된 정보의 압축 회수인지
- `setup_or_payoff`: 이후 이해를 위한 setup인지, 앞선 정보·약속의 callback/payoff인지
- 기존 `압축↔확대 / 대사↔지문 밀도 / 다음 전환 압력` 좌표

`serial_position`만으로 초반 회차를 우선하거나 후기 회차를 배제하지 않는다. 후기 회차의 새 인물·조직·공간·규칙 첫 소개는 첫 제시 산문의 주요 후보가 될 수 있고, 초반 회차라도 이미 학습된 정보를 회수하는 블록은 첫 소개 표면과 호환성이 낮을 수 있다.

### 11.2 문장 경계는 사슬 기능으로 감사한다

독립 단문의 **개수**를 줄이는 것을 목표로 하지 않는다. 각 마침표가 하나의 의미·운동 사슬을 어디에서 끊고 무엇을 집중시키는지 본다.

- `관찰 → 예상 → 조정 → 결과`가 하나의 판단 진행인데 이유 없이 각각 독립문으로 잘렸는가.
- `동작 시작 → 힘 전달 → 결과`가 하나의 운동 연쇄인데 신체 부위 체크리스트처럼 분절되었는가.
- 예: `발 → 허리 → 어깨 → 도구/주먹 → 결과`의 힘 전달이 실제 진행 감각을 잃고 항목 나열로 변했는가.
- 같은 사슬을 문장 안에서 결속했을 때 인과·시간·몸의 진행이 더 선명해지는가.

반대로 다음 독립 단문은 기능이 확인되면 보존한다.

- 발견
- 판정
- 전환
- 앞 문장군의 축적을 한 점으로 모으는 결론
- 장면·화말의 열린 고리

### 11.3 과교정 금지

- 단문을 줄이겠다고 서로 다른 판단·시간·행동을 한 장문에 강제로 합치지 않는다.
- 의미 사슬의 결속이 끝난 뒤 새로운 판단이 시작되면 새 문장 경계를 허용한다.
- 문장 결속은 자연스럽지만 화면 블록이 과밀하면 문장 논리를 다시 깨지 말고 문단 경계를 조정한다.
- 짧은 독립문이 기능적이라고 확인되면 문장 길이 통계를 맞추기 위해 제거하지 않는다.

### 11.4 첫 제시와 callback 산문 일반화 금지

- 이미 학습된 정보의 callback에서 가능한 생략·압축·단문을 first introduction에 그대로 적용하지 않는다.
- first introduction의 확대·복문·직접 설명을 이미 학습된 반복 정보에도 기계적으로 재사용하지 않는다.
- 동일 기능처럼 보여도 `reader_prior_knowledge / onboarding_load / setup_or_payoff`가 다르면 직접 표면 비교 적격성을 다시 판정한다.
- 구분 근거가 부족하면 `선택 조건 미확인`을 유지한다.

### 11.5 초고 후 추가 감사

다음이면 재검토한다.

- `짧은 문장이 많다`는 이유만으로 결속 가능한 사슬을 무조건 합침
- `긴 문장이 많다`는 이유만으로 하나의 사슬을 체크리스트식 단문으로 분해함
- 발견·판정·전환 단문까지 기계적으로 없앰
- 서로 다른 사고를 한 문장에 밀어 넣어 인과와 시간축이 흐려짐
- 문장 결속 문제와 화면 문단 밀도 문제를 같은 것으로 처리함
- 참고 PSE의 선행 학습 상태를 확인하지 않고 첫 제시와 callback을 같은 산문 표면으로 일반화함

새 영구 회차 DB·새 연구층·Schema v3는 만들지 않는다.
