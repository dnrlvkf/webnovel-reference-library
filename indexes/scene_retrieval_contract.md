# 통합 Source Scene 집필 검색 계약

> 목적: Source Scene의 실제 결합 사슬은 연구 증거로 보존하되, 집필 때 그 결합을 정답·탈락 조건·재현 뼈대로 사용하지 않게 한다.

## 1. 핵심 원칙

**결합은 연구할 때 보존하고, 집필할 때 강제하지 않는다.**

- Source Scene의 beat 사슬은 `observed_chain`이다. 원문에서 실제로 함께 일어난 선택의 복원이지 `recommended_chain`이 아니다.
- 장면 전체가 현재 집필 장면과 비슷해야 참고 가능한 것이 아니다. 한 장면의 캐릭터 판단, 관계 권리, 사건 운동, 정보 제시, 독자 그림, 표현 실현 중 일부만 참고할 수 있다.
- 장면에 함께 존재한 요소는 별도 인과 근거가 없으면 서로 필수 조건으로 묶지 않는다.
- 현재 작품의 캐릭터·관계·사건 조건이 외부 사례보다 우선한다.
- 참고작의 beat 수·순서·대사/지문/침묵/효과음 조합을 현재 장면의 기본 뼈대로 삼지 않는다.

## 2. 검색 단위 — 장면 전체 일치가 아니라 부분 문제

검색 전에 현재 장면을 다음과 같은 독립 문제로 분해한다.

- CHARACTER: 누가 무엇을 먼저 보고 무엇을 우선·두려워·감수하는가.
- RELATIONSHIP: 누가 질문·거절·명령·차단·결정·보고할 권리를 갖는가.
- EVENT: 어떤 선택이 현재 상태를 다음 상태로 바꾸는가.
- STORY: 독자가 무엇을 먼저 알고 무엇을 뒤늦게 재분류하는가.
- PROSE: 그 판단과 상호작용이 대사·지문·행동·침묵·효과음·문장/문단으로 어떻게 실현되는가.
- READER PICTURE: beat 뒤 독자가 물리·상황·캐릭터·관계·사건을 어떻게 새로 보게 되는가.

한 Source Scene은 이 중 하나만 일치해도 재독 후보가 될 수 있다.

## 3. 부분 일치와 불일치 경계

후보 Source Scene마다 최소한 다음을 적는다.

- `matched_problem`: 현재 장면과 실제로 맞는 문제
- `mismatch_boundary`: 관계·POV·목표·비용·사건 조건 중 다른 부분
- `usable_judgment`: 원문에서 다시 확인할 작가의 선택 이유
- `do_not_import`: 현재 작품에 그대로 가져오면 안 되는 표면·beat·권리 구조

불일치는 자동 탈락 사유가 아니다. 오히려 **어디까지만 참고할 수 있는지**를 알려 주는 경계 정보다.

## 4. 관찰된 결합과 필수 결합을 구분한다

Source Scene에서 `관찰 → 판단 → 질문 → 역질문 → 침묵 → 실행`이 실제로 이어졌더라도 다음을 자동 추론하지 않는다.

- 관찰을 쓰려면 역질문이 필요하다.
- 역질문을 쓰려면 침묵이 필요하다.
- 같은 기능이면 같은 beat 순서를 써야 한다.
- 같은 물리 행동이면 같은 효과음이 필요하다.

`함께 관찰됨`과 `인과적으로 필수임`은 다르다. 필수성은 같은 작품의 반복·변형·실패·반례가 확인될 때만 올린다.

## 5. 완전 일치 우대 금지

현재 장면과 표면 상황이 가장 비슷한 Source Scene을 자동으로 최우선하지 않는다.

예를 들어 현재 문제가 `상급자가 후배의 잘못을 문책하는 장면`이라도 다음을 서로 다른 원천에서 참고할 수 있다.

- 캐릭터가 무엇을 먼저 보는가
- 반대권과 결정권이 어떻게 다른가
- 책임 문제가 사실 판정에서 어떻게 이동하는가
- 대사와 지문이 어떻게 한 판단을 같이 만든다
- 독자가 사건의 의미를 언제 재분류하는가

표면 상황의 높은 유사성은 원작 장면 배열 복제 위험도 함께 높일 수 있다.

## 6. Source Scene → PVAR 안전장치

통합 Source Scene을 읽은 뒤 표현 선택까지 참고해야 한다면 가능한 경우 관련 PVAR를 확인한다.

- Source Scene: `이 조건에서 실제로 이렇게 결합되었다`를 보여 준다.
- PVAR: `가까운 기능도 다른 조건에서는 다르게 실현되었다`를 보여 준다.

PVAR가 없다고 Source Scene을 사용할 수 없는 것은 아니다. 다만 한 사례만 있을 때는 그 결합의 선택 조건을 더 좁게 확정하지 않는다.

## 7. 집필 검색 순서

1. 대상 작품의 native anchor, 캐릭터 판단, 관계 권리, 사건 목표를 먼저 읽는다.
2. 현재 장면의 문제를 CHARACTER / RELATIONSHIP / EVENT / STORY / PROSE 중 필요한 축으로 분해한다.
3. 각 부분 문제로 Source Scene을 찾는다. 장면 전체 일치를 요구하지 않는다.
4. 각 후보에 `matched_problem / mismatch_boundary / usable_judgment / do_not_import`를 적는다.
5. 원문으로 재진입해 실제 observed chain과 앞뒤 맥락을 확인한다.
6. 표현 선택이 필요하면 관련 PVAR/PSE에서 다른 실현과 선택 경계를 확인한다.
7. 외부 참고를 닫는다.
8. 대상 작품의 캐릭터·관계·사건·문체 계약으로 새 장면을 조립한다.
9. 초고 후 `결합 강제 감사`를 수행한다.

## 8. 장면용 임시 검색 패킷

집필 직전에는 각 외부 사례에서 다음만 남긴다.

- source scene / 원문 좌표
- matched_problem
- mismatch_boundary
- usable_judgment
- do_not_import
- 관련 PVAR/PSE가 있다면 확인한 변형·반례

외부 Source Scene의 전체 beat 순서를 임시 패킷의 기본 아웃라인으로 복사하지 않는다.

## 9. 결합 강제 감사

초고 뒤 다음을 확인한다.

- 참고 Source Scene의 beat 수와 순서를 이유 없이 따라갔는가.
- 참고 장면에 역질문·침묵·효과음·특정 행동이 있었다는 이유만으로 현재 장면에도 넣었는가.
- 현재 캐릭터의 판단에서 나오지 않은 발화·행동을 참고 장면 때문에 유지했는가.
- 현재 관계에 없는 질문권·명령권·거절권을 참고 장면에서 가져왔는가.
- 현재 사건이 요구하지 않는 중간 단계가 참고 장면과 닮기 위해 추가되었는가.
- 외부 사례와 다른 선택을 할 수 있었는데 `성공 사례니까`라는 이유로 같은 결합을 유지했는가.

하나라도 그렇다면 외부 사례가 `증거`에서 `템플릿`으로 변한 것이다. 해당 요소를 제거한 뒤 현재 작품 조건에서 다시 선택한다.

## 10. 완료 판정

검색이 끝날 때 다음을 말할 수 있어야 한다.

- 어떤 **부분 문제** 때문에 이 Source Scene을 읽었는가.
- 현재 장면과 무엇이 다르며 그 차이가 왜 중요한가.
- 원문에서 확인한 작가의 선택 이유 중 무엇만 가져오는가.
- 어떤 beat·표면·관계 구조는 가져오지 않는가.
- 관련 PVAR/PSE가 보여 준 다른 가능성은 무엇인가.
- 최종 장면의 결합이 참고작이 아니라 현재 캐릭터·관계·사건에서 발생했는가.

이 계약은 새 기법 ID나 새 스키마가 아니다. 기존 Source Scene·PVAR·PSE·CHARACTER·RELATIONSHIP·EVENT·STORY·PROSE를 집필 검색에서 안전하게 연결하기 위한 운영 규칙이다.
